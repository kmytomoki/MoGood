## 0. 結論（先に4点）

1. **`docs/事業プラン草案.md` §2.1 の「1つのDBでつなぐ製品はほぼ存在しない」は、そのままでは事実として弱い。**
   海外には統合型が既にあり（Cooklist / Samsung Food / NoWaste.ai）、国内でも2025年10月にパナソニックが **KitchenPocket**（在庫→レシピ→買い物リスト、**無料**）を出している。空白地帯の主張は「日本語圏 × 店頭での購入前判定 × 消費計算まで含む」まで**絞れば成立する**。審査で必ず突かれるので、先に絞って書き直すべき。

2. **最大の脅威は大手レシピアプリではなく、家電メーカー（パナソニック）と海外統合型である。**
   `docs/instruction.md` §7 のリスク表は「クックパッド・クラシルが在庫連携を実装したら」を想定しているが、実際にはもう別方向から埋まり始めている。

3. **「在庫管理 + レシピ提案 + 買い物リスト」は既に無料が相場になった。**
   pecco も KitchenPocket も無料。したがって `docs/事業プラン草案.md` §3.1 の課金境界（2〜5日先の献立計画を有料側に置く）は、**競合相場から見ても課金しにくい位置**にある。`20260818/収益モデル案.md` C-4 の指摘が、競合側からも裏づけられた形。

4. **月480円は国際相場から見れば安い側で、価格の高さが問題ではない。**
   Samsung Food の有料版は月 $6.99 / 年 $59.99（日本円で月1,000円前後、為替により変動）。480円は約半値。問題は価格水準ではなく、**払う時点でまだ価値が証明されていないこと**（`20260818/収益モデル案.md` §0-1 の結論と一致）。

## 1. 類似プロダクトの地図

MoGood のループ（①在庫 → ②レシピ → ③買い物リスト → ④店頭判定 → ⑤消費計算 → ⑥修正）のうち、各プロダクトがどこを埋めているかで並べる。

### 1.1 カバー範囲の比較

| プロダクト | 区分 | ① 在庫 | ② レシピ | ③ リスト | ④ 店頭判定 | ⑤ 消費計算 | 料金 |
|---|---|:--:|:--:|:--:|:--:|:--:|---|
| **MoGood（構想）** | 統合 | ○ | ○ | ○ | ○ | ○ | 無料＋月480円（仮置き） |
| **KitchenPocket**（パナソニック, 2025-10〜） | 家電連携統合 | ○ | ○ | ○ | × | × | **無料** |
| **Cooklist**（米） | 統合 | ○ | ○ | ○ | △ 価格比較あり | × | フリーミアム |
| **Samsung Food**（旧 Whisk） | 統合 | ○ | ○ | ○ | × | × | 無料＋$6.99/月 |
| **NoWaste / NoWaste.ai** | 在庫特化 | ○ | △ | △ | × | × | Pro 年 $5.99 等 |

### 1.2 とくに近い3つと、MoGood との差

**(a) KitchenPocket（パナソニック）— 国内で最も脅威**
2025年10月中旬提供開始。冷蔵庫の AI カメラ連携で庫内食材を認識し、約9,000件のレシピから庫内在庫に応じて提案、材料を買い物リストへ一括登録、対応調理家電へ調理プログラムを送信するところまで無料でつながっている。
- **差**: (1) パナソニック製キッチン家電の所有が前提で、対象世帯が限られる。(2) **店頭での購入前判定（④）がない**——価値は自宅内で完結する。(3) 消費量の自動引き落とし（⑤）がなく、在庫の鮮度維持はユーザー任せ。
- **示唆**: 「在庫→レシピ→買い物リスト」だけを訴求すると、**無料の大手と正面衝突する**。MoGood の訴求は ④⑤ に寄せるべき。

**(b) Cooklist（米）— 発想が最も近い**
ロイヤリティカード（会員カード）を店舗と連携し、購入履歴を自動でパントリーに取り込む。100万件超のレシピと在庫を突き合わせ、買い物リストと価格比較まで持つ。
- **差**: MoGood は購買データの自動取り込みを**意図的に採らない**（`docs/instruction.md` 確定事項10・§3.1、レシートOCR/POS を主軸にしない）。Cooklist の方式は日本ではカード連携の基盤が弱く、また **POS には賞味期限が含まれない**ため ⑤ の精度に効かない。
- **示唆**: 「入力させない」の実現手段として、向こうは**購買データ側**、MoGood は**買い物リスト経由のワンタップ確定**を選んだ。この選択の理由は説明できるようにしておく。ここは審査で「なぜレシート連携しないのか」と必ず聞かれる。

**(c) Samsung Food（旧 Whisk）— 価格の物差し**
AI 献立プラン、買い物リスト自動生成、パントリー管理、Galaxy 端末での写真からのカロリー推定、SmartThings 経由の調理家電連携。無料＋Food+（月 $6.99 / 年 $59.99）。
- **差**: 店頭での単価判定・個人の値動き台帳がない。日本語圏の食材・スーパー事情への最適化も弱い。
- **示唆**: **「AI 献立＋買い物リスト」に月1,000円前後を払う市場は既に存在する**。480円の価格根拠を「節約額」ではなく相場比較でも語れる。

### 1.3 空白地帯の言い直し（案）

現行（`docs/事業プラン草案.md` §2.1）:
> 「在庫 → レシピ → 買い物リスト → 店頭判定 → 消費反映」を1つのDBでつなぐ製品はほぼ存在しない。

**書き直し案**:
> 在庫→レシピ→買い物リストまでをつなぐ製品は国内外に既に存在する（KitchenPocket・Samsung Food・Cooklist）。しかしそのいずれも **「店頭で買う前のお得判定」と「調理による消費量の自動引き落とし」を同じ在庫DBに載せていない**。ループが自宅内で途切れており、店頭とキッチンをまたいで閉じた製品は見当たらない。MoGood はこの2ステップ（④⑤）で差別化する。

**この方が強い理由**: 「誰もやっていない」より「ここまでは各社やっているが、この2つだけが空いている」の方が、調べた形跡があり、かつ反証されにくい。

### 1.4 脅威度

| 順位 | 相手 | 脅威の中身 | 現実的な打ち手 |
|---|---|---|---|
| 1 | KitchenPocket（家電メーカー） | 無料 × 家電同梱の配布力。冷蔵庫カメラは入力コスト最小化の本命解でもある | 家電非依存（どの冷蔵庫でも使える）＋ ④⑤ で差別化。家電を買い替えない層が主戦場 |
| 2 | Cooklist 型（購買データ自動取込） | 「入力させない」を別ルートで解決済み。日本上陸 or 国内模倣がありうる | 期限（POSに無い）と消費計算で優位。国内カード連携の障壁が当面の時間稼ぎ |
| 3 | pecco 等の国内在庫レシピアプリ | 既に50万DL超。ユーザーが「もう持っている」状態 | 「リストからワンタップ確定＋消費自動引き落とし」で継続率の差を出す |
| 4 | クックパッド・クラシル | 在庫連携を実装すれば機能差は薄まる（`docs/instruction.md` §7 の想定どおり） | 蓄積データ（台帳・好み学習）の先行 |
| 5 | 単価計算アプリ・チラシアプリ | 単機能だが無料で普及 | すべて手入力・掲載品限定。スキャンで代替する |

## 2. 収益モデル案（`20260818/収益モデル案.md` の要約 ＋ 競合調査による更新）

### 2.1 前提として押さえること

- 支払意欲の問題は**価格水準ではなく、価値証明の前に課金が来ること**（`20260818/収益モデル案.md` §0）。競合調査もこれを支持する（Samsung Food は倍額で成立している）。
- 真の問題は**フリーミアムの原価構造**。`docs/事業プラン草案.md` §4.1 の仮置きでは無料1人あたり ▲27円/月、課金転換率4%で25人あたり ▲310円/月。**価格を下げても悪化する**。
- **新たな制約**: ①②③ は無料が相場（pecco・KitchenPocket）。**ここに課金の壁は置けない**。

### 2.2 案の一覧（系統別）

| 系統 | # | 案 | 評価 |
|---|---|---|---|
| **A: 払うタイミングをずらす** | A-1 | 節約額の後払い型 | 心理的には最強だがストア課金が成果報酬に非対応。実装困難 |
| | **A-2** | 節約保証（節約額が料金を下回れば翌月無料） | クーポン運用で実現可。算出根拠が弱いとクレーム源 |
| | **A-3** | **課金起点のゲート化**（在庫が2週間続いたら課金開始） | 価値証明の後に課金。物差しが Phase 0-① と同一。**有力** |
| | A-4 | 回数プリペイド（スキャン100回パック等） | **原価と収益が構造的に連動する唯一の案**。ARPU は低い |
| | **A-5** | **世帯課金**（1契約で在庫DBを共有） | 献立は世帯の課題。CAC 据え置きで ARPU 上昇。**低コストで効く** |
| **B: ユーザー以外が払う** | **B-1** | **リワード広告を原価に直結**（動画1本でスキャン1回） | 節約層は金でなく時間で払う。▲27円/月の穴埋めに現実的。**有力** |
| | B-2 | 食品メーカーの文脈型タイアップ | 端末側マッチングなら確定事項8と両立。**提案の中立性への信頼を削る**のが最大リスク |
| | B-3 | ネットスーパー・生協の注文連携（成果報酬） | 「安く買う」訴求と逆行しうる |
| | **B-4** | **自治体のフードロス削減予算**（実証事業・共同研究） | **現段階で最初に現金を得る最現実的な経路**。要調査 |
| | B-5 | 食育・家庭科の教材ライセンス | 高校生チームという立場が効く希少市場。単価小だが実績になる |
| | B-6 | 企業の福利厚生バンドル | 中期。営業力が必要で現段階は非現実的 |
| **C: 訴求の付け替え** | C-1 | 売り物を「節約」から「時間」へ | 「月2,000円節約」は疑われるが「毎日15分が消える」は疑われにくい |
| | C-2 | 表示単位の変更（1日16円 / 今月の節約2,400円） | 支出でなく回収の話に見せる |
| | C-3 | ポイント経済との接続 | 現金より抵抗が低い。認知施策としても効く |
| | **C-4** | **課金境界の見直し** | 献立計画（＝ループの入口）を有料側から外し、**買い物台帳・節約レポート・好み学習**（蓄積して効く＝解約しにくい）へ寄せる。**競合調査でも裏づけ**（§2.1） |
| **D: 原価側** | D-1 | 定番レシピ・商品の事前バッチ生成＋キャッシュ | A〜B のどれを選んでも**必須**。損益への効き方は収益案と同等 |
| | D-2 | 無料ユーザーは「その日の共通献立候補」から選ばせる | 1日1回の生成を多人数で割る |
| | D-3 | 単価換算・消費量計算はルールベースで原価0 | 既に確定事項7・§4.1 |

## 3. 競合を踏まえて変えるべき点（今回の調査による追加）

1. **無料版の位置づけを守りに回す。** ①②③ を無料で出すのは競合相場に合わせるためであり、それ自体は差別化にならない。無料の役目は「④⑤ を体験させるまでの導線」と割り切る。
2. **有料の中身を C-4 の方向へ寄せる。** 献立計画を有料の壁にすると、無料の KitchenPocket・pecco に対して見劣りする。有料は**台帳・節約レポート・好み学習**（＝蓄積して効く＝他社が模倣しても追いつけない）に置く。
3. **家電非依存を明示的な強みとして書く。** KitchenPocket は冷蔵庫の買い替えが前提。MoGood は既存のどの冷蔵庫でも今日から使える。
4. **「なぜレシート/購買データ連携をしないのか」への回答を用意する。** Cooklist が実在する以上、必ず問われる。回答は `docs/instruction.md` §3.1 に既にある（買う前の判断に間に合わない／POSに賞味期限がない）。
