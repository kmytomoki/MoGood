# 友人・家族へのアンケート／ヒアリング手順

対象: よく自炊・買い物する友人・家族（一人暮らし=二次ペルソナ寄り、家庭の食事担当=一次ペルソナ寄り）  
目的: 「アプリ欲しい？」ではなく、**「把握→献立→買い物→調理」の毎日のループに痛みが実在するか**を確認する  
注意: 友人・家族は好意で「いいね」と言いやすい。**過去の具体エピソード**を優先し、感想は割引して読む。

---

## 0. 先に決めること

### 今検証したい仮説（これ以外は深追いしない）

1. 「今日何作ろう」を考えること自体が負担である（毎日繰り返すから）
2. 冷蔵庫の中身を正確に把握できておらず、二重買い・買い忘れ・腐らせが起きている
3. 「どの店・どの商品が安いのか、相場が分からない」と感じている
4. 店頭で容量・パック差の比較に手間を感じた／諦めたことがある
5. 冷蔵庫管理・家計簿系アプリは**入力が面倒**で続かなかった（→「入力させない設計」の裏付け）
6. 棚をスマホで撮る行為に抵抗がある／ない
7. （参考）月いくらまでなら払うか ← 友人の数字は当てにならないので参考止め

### 対象者の条件（スクリーニング）

次に当てはまる人を優先する。

- 自分の食事（または家族の食事）の献立と買い物を自分で回している
- スーパー／ドラッグストアに **週2回以上**、または食材をよく買う
- 自炊が週に数回以上ある（完全外食勢は後回しでよい）

**避けた方がよい相手（最初の何人かでは）**

- 底値ノートを自作するような節約ガチ勢（精度クレーム前提になりやすい）
- 「何でも応援するよ」だけの関係で、買い物の話を具体的にしてくれない人

目標人数の目安: **ヒアリング 5〜8人** ＋ **短いアンケート 15〜30人**（友人経由の拡散可）。少なくてよいので質を取る。

## 1. 声のかけ方（最初の一文）

アプリの話を先に出さない。

**よい例**

> 卒研／プロジェクトで「毎日のごはんづくりと買い物のやり方」を調べていて、よく自炊する人の話を15分だけ聞かせてほしい。正解はないし、売り込むものもない。メモしてよい？

**悪い例**

> 冷蔵庫管理と献立提案のアプリ作ってるんだけど、使う？便利だと思う？

家族には「授業の課題の取材」と言うと構えられにくい。友人には「インタビュー協力」と明示し、終わったら何か奢る／お菓子を渡すと続きやすい。

## 2. ヒアリング（推奨・15〜20分）

形式: 対面 or 通話。録音は許可を取ってから（後で聞き返す用）。  
進め方: **最近の1日（献立決め→買い物→調理）**を時系列でたどる。抽象論に逃げさせない。

### オープニング（1分）

- 週に何回くらいスーパー行く？主な店は？
- ごはんは週何回くらい作る？

### 本題A: 直近の「献立決め→買い物→調理」を再現（8分）

「この前ごはんを作った日」を指定させる。

1. その日のメニューはいつ・どうやって決めた？（前日？店で？冷蔵庫を見て？）
2. 決める前に冷蔵庫の中身は把握してた？どうやって？（開けて見た／記憶／写真）
3. 買い物リストは作った？（紙・スマホ・頭の中）
4. 店では、同じもの（肉・牛乳・卵など）で似た商品が並んでいた？**どうやって選んだ？**（いつもの／安い見た目／100gあたり／特売シール／迷って適当）
5. 「どっちが得か分からなかった」「この店は高いのか安いのか分からない」と感じた場面は？具体的に何と何？
6. 帰宅後、買ったのに既にあった（二重買い）・買い忘れはあった？
7. 買い物〜調理まで、全体で何分くらい？どこが一番面倒だった？

### 本題B: 痛みの強さ（3分）

- 「今日何作ろう」を考えるのは、正直どれくらい面倒？（毎日のことか、たまにか）
- 食材を腐らせた・余らせた最近の例は？そのとき何が原因だった？（存在を忘れてた／期限を知らなかった／献立に組み込めなかった）
- 「高い／安いの感覚（相場観）」は自分にある方？ない方？

### 本題C: 解決手段の現状（3分）

- 冷蔵庫管理・献立・家計簿系のアプリを入れたことある？続いた？**やめたなら何が面倒だった？**（ここは深掘りポイント。入力の面倒さが出たら具体的にどの操作か聞く）
- 単価表示（店の100gあたり）は見る？信じている？
- 店内でスマホはよく触る？（チラシ・決済・メッセージ・レシピ検索）

### 本題D: アイデアへの反応（2分）※ここで初めてアイデアに近づける

アイデアを長く説明しない。一文ずつ、反応を分けて見る。

> ① もし「冷蔵庫の中身が自動で管理されて、それを使い切る献立を毎日提案してくれる」としたら、この1週間で使ったと思う？

> ② 「作りたい献立の足りない食材だけが買い物リストになって、買ったらチェックするだけで在庫に反映される」としたら？

> ③ 「店で気になる商品を撮るだけで、どれが得か・いつもより安いかが分かる」としたら、前回の買い物で使った？

続けて必ず聞く:

- 一番ほしいのは①②③のどれ？いらないのはどれ？（**機能ごとの温度差**が v2.0 の優先順位検証になる）
- 使わないとしたら、何が引っかかる？（登録が面倒そう／提案が口に合わなそう／恥ずかしい／精度不安）
- 店で撮影、抵抗ある？

### クロージング

- 他に「毎日のごはんづくり・食費で困ってること」ある？
- 同じ境遇の友人を1人紹介できる？（任意）
- お礼

### 聞き手がやってはいけないこと

- 「便利でしょ？」と誘導する
- 機能一覧を最初から説明する
- 「月480円なら？」を長々と詰める（友人価格は当てにならない）
- 沈黙を埋めに自分の仮説を喋る

## 3. アンケート（短い・拡散用）

ヒアリングのあと、または並行で。**3〜5分・問数は12問前後**。Googleフォームでよい。
紙で配る場合は `docs/アンケート用紙_チェック式.md` を使う（質問は同じ構成）。

冒頭文例:

> 自炊やスーパーでの買い物をよくする方へ。毎日のごはんづくりと買い方の調査です（授業／プロジェクト）。匿名でOK。売り込む商品はありません。

### 質問構成（チェック式用紙と対応）

1. 属性: 住まい／来店頻度／自炊頻度
2. 献立: いつ決めるか／考える負担感
3. 冷蔵庫: 外出先で思い出せず困った経験（二重買い）／捨てた経験
4. 買い物: リストを作る習慣／似た商品の選び方／「どっちが得か」で困った経験／相場が分からない感覚
5. アプリ: 冷蔵庫管理・家計簿アプリの利用/挫折経験と**やめた理由**
6. 撮影許容: 店内での撮影抵抗
7. アイデア受容: 「自動管理+献立提案+リスト+撮るだけ判定」への反応と、使わない理由
8. 任意: 一番の困りごと（自由記述）／支払意欲

### アンケートで信じすぎない数字

- 「使ってみたい」の割合（友人経由は上振れする）
- 「月いくら払うか」

### アンケートで見るべき数字

- 献立を考えるのが「負担」以上の割合（仮説1の根幹）
- 二重買い・捨てた経験が「たまにある」以上の割合（在庫管理の痛みの実在）
- アプリ挫折理由に「**入力が面倒**」が占める割合（入力させない設計の裏付け）
- 撮影抵抗（店頭スキャン機能の致命傷になりうる）
- 「相場が分からない」の頻度（お得判定機能の需要）

## 4. メモの取り方（1人1枚テンプレ）

1人終了ごとに、共有シートに書く（録音全文起こしは不要）。

| 項目 | 記入 |
|---|---|
| 誰（匿名可）・属性 | 例: 友人A・28歳・一人暮らし・週3回 |
| 献立の決め方・負担感 | |
| 冷蔵庫の把握方法／二重買い・腐らせの具体例 | あり／なし＋内容 |
| 買い物リストの習慣 | |
| 得か損かで困った具体例・相場観 | |
| アプリの利用/挫折経験と理由 | |
| 撮影への抵抗 | |
| ①献立提案 ②リスト連動 ③撮るだけ判定 の温度差 | 例: ①強 ②中 ③弱 |
| Unexpected（予想外） | |
| 信頼度 | 具体エピソード多め＝高／感想だけ＝低 |

班で5人分並んだら、次だけ集計する。

- 「献立を考えるのが負担」だった人数
- 「二重買い・腐らせ」の具体例があった人数
- アプリ挫折理由の内訳（入力が面倒／効果なし／その他）
- ①②③の機能別の温度差の傾向
- 「撮影抵抗あり」の人数

## 5. 友人・家族バイアスへの対処

| 起きやすいこと | 対処 |
|---|---|
| 「絶対使う！」 | 「この1週間のどの日・どの場面で使う？」と具体に戻す |
| 機能要望が増える | メモはするが、コアループ検証中は実装しない |
| 身内だけ陽性 | 友人の友人を1段だけ紹介してもらう／学内の一人暮らしにも同じ質問 |
| 自分が誘導してしまう | 質問リストを読み上げる。仮説（本題D）は最後の2分だけ |

## 6. AI班・アプリ班への渡し方

ヒアリング結果は次の形で共有すると開発に効く。

- **AI班**: 「読めないと困る棚・ラベル」の例（手書き値札・密集・暗い）→ 検証用撮影の参考。「提案が口に合わなそう」の声 → レシピ提案プロンプトの好み反映の参考
- **アプリ班**: 「アプリをやめた理由（どの入力操作が面倒だったか）」→ 在庫・リスト画面の設計に直結。「撮影が恥ずかしい」→ スキャンUIの心理ハードル
- **共通**: ①②③の機能別温度差 → 開発フェーズの優先順位の再確認材料

`instruction.md` の勝ち筋（ループがつながる・入力させない）を否定する声（例:「別々のアプリで十分」「登録はどうせしない」）が複数出たら、事業仮説の見直し議題にする。応援の「いいね」だけでは見直さない。
