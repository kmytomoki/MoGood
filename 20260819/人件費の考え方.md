# 収支計画における人件費の考え方

作成日: 2026-08-19 / ステータス: **提案（未反映・CEO 判断待ち）**
対象: `docs/エントリーシート記入内容.md` §6 収支計画
関連: `20260818/収支再計算.md` §5 / `docs/事業プラン草案.md` §4

## 0. 結論（先に3点）

1. **1年後の「人件費 0円」は会計的には正しい。** 実際に給与を支払わないなら費用は発生しない。**変える必要はない。**
   ただし**注記なしで 0円 と書くと、審査で「自分たちの労働をタダで計上している」と読まれる。** 表は 0円 のまま、注記で帰属人件費（無償で投じている労働の時給換算）を明示するのが最善。

2. **本当の問題は3年後の「月10万円」である。** この数字は**必要額ではなく、払える額から逆算されている。**
   3年後の粗利から広告費・その他経費を引いた残りが月約11.8万円で、そこに収まるよう月10万円が置かれている。順序が逆であり、指摘されると弱い。

3. **人件費を現実的な水準にすると、3年後も赤字になる。**
   業務委託エンジニア1人（月40万円 = 年480万円）を入れると、3年後の利益 22.1万円 → **▲337.9万円**。
   これは隠すべき事実ではなく、**「専任を雇える規模はいつ来るか」を示すことで前向きな材料に変えられる**（§3）。

## 2. 1年後の「0円」をどう扱うか

### 2.1 3つの選択肢

| 案 | 内容 | 評価 |
|---|---|---|
| **A** | 0円のまま・注記なし（現状） | **弱い。** 審査で「あなたたちの人件費は？」と聞かれた時に準備がない状態 |
| **B** | **0円のまま・注記で帰属人件費を明示** | **推奨。** 会計的に正しく、かつコストを認識していることを先回りで示せる |
| **C** | 本表に計上する | **採らない。** 全年度が赤字になり、プラン自体が成立しないように見える。実際に支払っていない費用を計上するのは会計的にも不正確 |

### 2.2 推奨する注記の書き方（案B）

> **人件費について**: 1年後の人件費は 0 円としている。在学中のメンバーが自ら開発するため、実際の支払いが発生しないためである。
> ただし、これは労働に価値がないという意味ではない。メンバー〇名が月あたり約〇〇時間を投じており、最低賃金【要確認: 令和8年度・該当都道府県の額】で換算すると年間およそ〇〇万円に相当する労働を無償で投入している。
> **この無償の労働に頼っている点が、本計画の最大の前提である。** メンバーの卒業後も事業を続けるには、人件費を支払える水準まで収益を伸ばす必要があり、その規模を §〇 に示した。

**要記入項目**（実態に合わせて埋めること）:
- メンバー人数
- 1人あたりの月間投入時間（実績で書く。多めに盛らない）
- 該当都道府県の令和8年度・最低賃金【一次情報で要確認】

**なぜ最低賃金で換算するか**: エンジニア相場（時給3,000〜5,000円）で換算すると金額が過大に見え、「盛っている」と受け取られる。最低賃金なら**最も控えめな見積もり**であり、それでもこれだけかかるという説得力が出る。

### 2.3 効果

1年後の売上高は 8.6万円。仮に帰属人件費が年150万円前後なら、**売上の約18倍の労働を無償で投じて事業を成立させている**ことになる。これを自分から書くことで:

- 「学生だから人件費0で当然」という甘い計画ではなく、**コストを直視した計画**に見える
- 審査員の想定質問（「卒業後どうするのか」）を先回りできる
- §3 の「専任を雇える規模」の議論に自然につながる

## 3. 3年後の「月10万円」の問題

### 3.1 この数字は必要額ではなく残額である

3年後の数字を分解すると:

| 項目 | 年額 | 月額 |
|---|---|---|
| 売上高 | 432.0万円 | 36.0万円 |
| 売上原価 | 193.9万円 | 16.2万円 |
| **粗利** | **238.1万円** | **19.8万円** |
| 経費（広告60 + その他36） | 96.0万円 | 8.0万円 |
| **人件費に回せる上限** | **142.1万円** | **11.8万円** |
| 実際の計上額 | 120.0万円 | 10.0万円 |

**月10万円は「11.8万円に収まる額」として置かれている。** つまり黒字22.1万円は、人件費を残額に合わせた結果である。

### 3.2 月10万円で何が雇えるか

月10万円は、開発・運用を担う人員の相場から見ると **週1日程度のスポット業務委託**に相当する。MoGood は次を運用する必要がある。

- モバイルアプリ（iOS / Android）の保守とストア対応
- バックエンドと在庫DBの運用
- VLM/LLM API の呼び出し監視とコスト管理、キャッシュ設計の改善
- 障害対応（店頭で使われるため、レイテンシと可用性が価値に直結する）

**月10万円では回らない。** ここを突かれた時に「回ります」と答えると、計画全体の信頼が落ちる。

### 3.3 人件費を現実的にした場合

| 前提 | 年額人件費 | 3年後の利益 |
|---|---|---|
| 現状（月10万円） | 120万円 | **+22.1万円** |
| 業務委託エンジニア1人（月40万円） | 480万円 | **▲337.9万円** |
| 正社員1人（年収400万＋法定福利費等25%） | 500万円 | **▲357.9万円** |

**3年後の黒字は、人件費の置き方だけで消える。** これが現計画で最も脆い箇所。

## 4. 推奨する書き換え方針

### 4.1 「いつ専任を雇えるか」を逆算して示す

隠すのではなく、**規模の目標として提示する**のが最も強い。

3年後の前提における1人あたりの月次貢献:

| 項目 | 値 |
|---|---|
| 有料1人の手取り | 480円 × 0.85 = 408円 |
| 有料1人のAPI原価 | ▲18円 |
| 有料1人が支える無料ユーザーの原価（転換率5% = 無料19人分） | ▲125円 |
| **有料1人あたりの実質粗利** | **約265円/月** |

専任1人（月40万円）＋その他経費（月8万円）＝ 月48万円を賄うのに必要な規模:

> 480,000円 ÷ 265円 ≒ **有料 約1,800人 → MAU 約36,000人**（転換率5%想定）

3年後の想定は MAU 20,000人・有料750人。**専任1人を雇うには、その約2倍の規模が要る。**

### 4.2 書き方の案

> 3年後の人件費 120万円は、外部への部分委託（保守・スポット対応）を想定した額であり、専任者を雇用できる水準ではない。
> 現在の単位経済では、有料利用者1人あたりの実質粗利は月約265円であり、専任1人（月40万円）を賄うには有料約1,800人、月間利用者にして約36,000人の規模が必要になる【いずれも仮置きの前提に基づく試算】。
> したがって3年後は、創業メンバーが開発の主体を担い続けることを前提とする。**専任者の雇用は4年目以降の目標**とし、そこに至るには利用者数の拡大よりも先に、1回あたりの AI 利用料の圧縮（撮影0.3円・提案0.1円）を実現する必要がある。

**この書き方の利点**: 弱点を認めながら、「では何を達成すればよいか」を数字で示している。審査員が見たいのは完璧な黒字計画ではなく、**自分の計画の限界を把握しているか**である。
