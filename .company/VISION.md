# MoGood — ビジョン / ミッション

最終更新: 2026-08-17 / 出典: `docs/instruction.md`（v2.0）・`docs/事業プラン草案.md`

## ミッション

毎日繰り返される「冷蔵庫を把握する → 献立を考える → 買い物へ行く → 店頭でどれが得か選ぶ → 調理して減った分を把握する」というサイクルの負担を、AI に代わりに回させてなくす。

一行で言うと: **考えずに、回る。**

## 長期ビジョン

生活の各領域（食品 → 日用品ストック → 家計）を、DB 上で AI エージェントに継続管理させる **life-agent** 構想。本プロジェクトはその第1弾（食品ドメイン）であり、ここで作る基盤（在庫 DB + AI エージェント）は第2弾以降へ流用する前提で設計する。

## 中核価値（見失ってはいけないもの）

1. **主役はループ全体がつながっていること** — 冷蔵庫管理・レシピ・買い物リスト・単価計算は単機能アプリなら既存。1つの在庫 DB を介して毎日のサイクルとして一気通貫でつながることが唯一の差別化。個々の機能で勝負しない。
2. **入力コストの最小化が生命線** — 在庫 DB の鮮度が落ちた瞬間、レシピ提案も買い物リストも信用を失いループが死ぬ。「ユーザーに入力させない」設計を最優先。
3. **店頭では「買う前」に効く** — 買った後に価格が分かっても意味がない。棚の前で共通単価に換算して購入前に示す。
4. **堀は技術ではなく蓄積データ** — 在庫・消費の履歴、個人の買い物台帳、選択履歴からの好み学習。使うほど馴染む＝乗り換えコスト。技術的参入障壁はないと正直に認める。

## やらないこと（確定）

- 店舗間のリアルタイム価格比較
- ユーザー投稿型（クラウドソース）の価格共有・価格データの公開
- スマートグラス対応
- 自前の画像認識モデルの学習・ファインチューニング
- レシートOCRを入力の主軸にすること
- 小売連携・価格データ提供による収益化

詳細と理由は `docs/instruction.md` §3（確定した設計判断）・§8（禁止事項）を参照。**再提案・蒸し返しをしない。**
